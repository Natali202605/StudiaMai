# Выкладка и откат

## Сейчас

Ветка `security/personal-data-intake` не включает приём заявок. Публичные тексты и фото остаются в файлах сайта. Пока ветка не слита, опубликованный сайт эту защиту не получает.

## Перед включением приёма

1. Отозвать опубликованный токен внешнего хранилища и больше не вставлять его в клиентский код.
2. Сменить пароль, который раньше был в коде админки, и не хранить новый пароль в репозитории.
3. Просмотреть историю Git и архивы после отзыва секретов. Очистка истории делается отдельно и только осознанно: она не заменяет отзыв секрета.
4. Заполнить `.env` по `.env.example` на сервере, не в Git: секрет сессии, пароль первого администратора, список разрешённых адресов сайта.
5. Поднять собственный HTTPS API и приватную базу вне публичного каталога. Хостинг в этом документе не выбирается.
6. Убедиться, что по HTTP не открываются `.env`, `server/`, база и копии.
7. Утвердить тексты и сроки. Только после этого оператор может поставить в `data/intake.json` значение `enabled: true`.

Сервер в этой ветке при верной заявке всё равно отвечает отказом, пока маршрут включения не будет отдельно принят владельцем.

## Откат

Откат ветки возвращает прежнюю отправку заявок из браузера и прежний клиентский файл с секретом записи. Перед откатом секрет уже должен быть отозван. Откат не удаляет заявки, потому что новая ветка их не записывала.
