# Аудит сбора заявок

Дата: 11 октября 2026 года. Проверены исходники репозитория. Это не подтверждение работающего сервера и не вывод о соответствии Закону № 152-ФЗ.

## Что было

- На GitHub Pages API по умолчанию пустой (`js/config.js`). Файл `server/server.js` сам по себе сервер не запускает.
- Без API браузер мог отправлять текст заявки в FormSubmit, Web3Forms, Telegram или произвольный URL и дополнительно писал заявку в `localStorage`.
- В публичном клиентском файле хранился токен записи внешнего хранилища настроек. Значение здесь не приводится. Его нужно отозвать и заменить владельцу. Удаление строки из нового коммита не отменяет прежнюю публикацию.
- Пароль админки проверялся в браузере и мог сохраняться в `localStorage`. На странице входа пароль показывался открытым текстом. Это не серверная защита.
- `express.static` отдавал корень проекта, поэтому при запуске этого сервера файл базы внутри дерева мог стать доступен по HTTP. Факт такой отдачи с работающего сервера не проверялся.
- Согласие на сервере приводилось через `Boolean(...)`, поэтому строка `"false"` считалась согласием.
- Новые отзывы могли сразу попадать в слайдер.

## Что изменено в этой ветке

- Приём заявок выключен флагом `data/intake.json`. Форма показывает, что данные не сохраняются, и предлагает позвонить.
- Отправка в FormSubmit, Web3Forms, Telegram и произвольный URL из браузера убрана.
- Заявка не пишется в `localStorage`.
- В форме остались необязательное имя и обязательный телефон. Фамилия, email и свободный комментарий убраны.
- Рядом с пустым чекбоксом стоят ссылки на существующие тексты согласия и политики. Эти тексты остаются черновиками до утверждения оператором.
- Серверная функция `validateCallbackRequest` принимает только `consent === true` и известные версии документов. Даже при верных полях текущий маршрут `/api/bookings` отвечает отказом, потому что приём не включён.
- Открытая регистрация администратора и автоматическая публикация нового отзыва отключены.
- Статическая раздача корня проекта заменена на отдельные каталоги `css`, `js`, `images`, `admin` и короткий список страниц и публичных JSON.
- Публичная конфигурация отдаёт только признак `intakeEnabled`.
- Автозагрузка Google Fonts снята. Внешние ссылки записи остаются прямыми и срабатывают только по нажатию.
- Уже размещённые 49 отзывов не удалялись.

## Проверки

Файл `tests/intake-policy.test.mjs` описывает проверки согласия и лишних полей. На этом компьютере команды `node` нет, поэтому он не запускался. Запущен `tests/intake-policy.test.ps1`: он проверяет те же правила телефона и согласия и то, что публичные скрипты больше не вызывают чужие сервисы заявок и не подключают шрифты Google. Рабочий хостинг, почта, база и админка с реальными данными не проверялись. Реальные заявки не отправлялись.

## Что ещё не сделано

- Сессия администратора по-прежнему задумана как подписанный токен в ответе API, а не как cookie `HttpOnly`. MFA для входа не подключена.
- Хранилище сервера остаётся файлом JSON, а не отдельной транзакционной базой вне публичного каталога. Рабочий сервер без секретов в окружении не запускается.
- Заголовки CSP на хостинге не выставлялись: на страницах есть встроенные скрипты. Мета-тег вместо серверного заголовка не добавлялся.
- Файлы шрифтов в репозиторий не клались. Убран только запрос к Google Fonts при загрузке страницы.
- История Git по-прежнему содержит ранее опубликованные секрет записи и пароль админки. Их нужно отозвать. История в этой задаче не переписывалась.
- Ветка не публиковалась. Открытый сайт на GitHub Pages эту защиту не получает, пока ветку отдельно не выложат.

## Условия включения приёма

Оператор подтверждает себя, тексты, место базы в выбранной инфраструктуре, сроки, замену опубликованных секретов и результат отдельной проверки. После этого владелец сам меняет флаг и запускает сервер. Код этого не делает.
